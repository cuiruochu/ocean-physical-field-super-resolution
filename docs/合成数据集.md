# 合成数据集

这一部分用于说明，我在硕士毕业论文中是如何对原始 `ERA5` 数据进行降质，并构建 `LR-HR` 配对样本的。

需要先说明的是，这种“合成数据集”方案主要用于研究和 benchmark，对工程落地价值的支撑是有限的。因为它本质上是在：

- 从原始 `ERA5` 出发
- 构造一个降质版本的 `ERA5`
- 再让神经网络去恢复回原始 `ERA5`

因此，它更适合用于验证网络结构本身的效果，而不是证明该方案已经具备真实业务场景下的应用价值。

## 基本思路

合成数据集的构造方式很直接：

- 把原始 `ERA5` 物理场视为 `HR`
- 对原始 `ERA5` 做 `Bicubic` 下采样，得到 `LR`
- 将二者按同一时间点、同一变量组成监督学习所需的配对样本

也就是说，单个样本的本质是：

- 输入：由原始 `ERA5` 降质得到的 `LR`
- 标签：未降质的原始 `ERA5`

## 样本构造流程

对于某一个确定的时间点和某一个确定的变量，处理流程如下：

1. 从原始 `ERA5` 数据中取出一个二维物理场数组。
2. 将这个二维数组视为当前样本的 `HR`。
3. 在实现上，将这个二维数组整理成三维张量，第一维是通道维，固定为 `1`。
4. 使用 `torchvision` 提供的 `resize` 函数，并指定 `Bicubic` 插值，对该三维张量执行下采样。
4. 下采样后的结果作为 `LR`。
5. 将这对 `LR-HR` 样本保存下来，用于训练、验证或测试。

在这个过程中：

- `HR` 不做额外退化
- `LR` 的退化方式主要就是 `Bicubic` 下采样
- 一般不额外叠加噪声、模糊核估计误差或其他复杂退化过程

因此，这是一种比较标准、也比较理想化的超分辨率合成数据构造方式。

如果只看“降质”这一步，在代码层面，我当时采用的是 `torchvision.transforms.functional.resize`。下面给出一个最小示例。这个示例不是直接读取真实 `ERA5` 数据，而是先随机初始化一个三维张量，用来说明调用方式。

```python
import torch
from torchvision.transforms.functional import resize
from torchvision.transforms import InterpolationMode

# 随机初始化一个三维张量，维度顺序是 (C, H, W)
# 其中通道维固定为 1
hr = torch.rand(1, 90, 60, dtype=torch.float32)

# 例如把高分辨率样本降到更低分辨率
lr = resize(
    hr,
    size=[45, 30],
    interpolation=InterpolationMode.BICUBIC,
    antialias=True,
)

print(hr.shape)  # torch.Size([1, 90, 60])
print(lr.shape)  # torch.Size([1, 45, 30])
```

## 配对关系

这种构造方式下，样本之间的配对关系是完全确定的：

- 同一个时间点
- 同一个变量
- 同一份原始 `ERA5`

只是空间分辨率不同。

因此，在数据组织上，通常可以把它理解为：

- `HR` 是原始 `ERA5`
- `LR` 是从该 `HR` 直接降质得到的结果

它并不涉及跨数据源配对，也不涉及 ERA5 与其他产品之间的时空对齐问题。

## 这种方案的局限性

这种“合成数据集”方案的最大问题在于：

- 它并不能提供比原始 `ERA5` 更高分辨率、更高质量、或者更难获取的真实目标

换句话说，这种训练任务本质上只是：

- 从一个被降质的 `ERA5` 恢复出原始 `ERA5`

因此，它能够说明的主要是：

- 某个网络结构在这个合成 benchmark 上是否有效

但它不能自然推出：

- 该网络是否真正具备工程落地价值
- 该网络是否能够逼近真实高分辨率数值求解结果
- 该网络是否能在真实下游任务中替代高成本 `HR` 数据

## 与当前项目的关系

当前项目后续整理的 `ERA5 -> CMEMS` 方案，与这里的“合成数据集”方案是两条不同路线：

- “合成数据集”路线：`ERA5` 降质后再恢复到原始 `ERA5`
- 当前项目路线：把 `ERA5` 作为 `LR`，把 `CMEMS` 产品作为 `HR`

前者更适合做纯 benchmark 研究；后者虽然仍然存在局限性，但至少更接近“利用低分辨率产品去近似高分辨率产品”的真实任务设定。
